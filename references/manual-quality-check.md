# 人工质量检查

本文件用于提交完整攻略或 HTML 产物前的 agent 质量自检。脚本可以检查输出入口、互链和资源引用；本文件只检查需要语义判断的结果质量。

## 使用时机

提交完整攻略、每日页、城市页或静态 HTML 产物前，必须执行本检查。

如果只是回答一个小问题、整理一小段文字、或还处在路线解析/事实填充中间阶段，不需要提前读取本文件。

## 检查清单

- 是否只使用了用户提供、用户授权或 [pre-render-online-research.md](pre-render-online-research.md) 明确允许查询的材料。
- 每个 `route_places` 真实游玩/短停地点是否都已处理：有可用内容时写入对应每日页，材料不足但影响执行时标注 `材料未说明` 或 `需出行前确认`。
- 每日景点详情是否只包含用户路线中的 `route_places`，且没有把停车场、游客中心、入口、码头、车站、餐厅、酒店等设施拼进景点标题。
- 城市页是否只为通过独立增量价值判断的城市生成；每个路线城市的角色是否已说明，或已判断不需要单独城市页。
- 照片是否只来自输入材料文件夹，且只按目录名、文件名和路径归属展示；进入 `route_places` 的县城、老城、街区、古镇或观景台如有可归属本地照片，也必须展示。
- 是否只保留对出行决策有帮助的缺失信息和关键冲突；普通空缺不写 `材料未说明`，影响执行的冲突必须并列说明。
- 最终文案是否可直接执行：删除重复内容、套话、弱相关背景和空小节；当天 timeline 只写路线、转场和执行提醒，不加入用户未要求的餐饮、购物或自由发挥安排。

## 脚本校验边界

输出目录、`index.html`、本地链接目标和远程资源引用等机械检查由 `node scripts/verify_output.mjs` 执行。CSS、viewport、导航、timeline、生成时间、照片 DOM 结构等 EJS 模板固定的结构不再重复校验。

如果脚本校验和人工检查都适用，先处理对应流程中未完成的 retrieval/digest review 项或事实来源缺口，再修正文案和 `facts-workspace.json` 中的事实问题，最后重新渲染并运行脚本校验。
